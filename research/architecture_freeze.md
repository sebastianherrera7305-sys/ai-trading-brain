## 3. What "frozen" means

1. `research/graph.py` regenerates `graph_snapshot.json` + `graph_report.md`
   after every store or document change, and **always before committing a
   campaign closure** (knowledge_graph.md §7).
2. The graph is a generated view; it is never edited by hand. If it is
   inconsistent with the registries, fix the registries, not the snapshot.
3. New entity or edge types require a spec update in `knowledge_graph.md`
   first (maintenance rule 4).
4. The dashboard is generated by `generate_dashboard.py`; no manual edits.
5. Architecture changes (new registries, new stores, doc reorganization)
   require a justification entry in `research/meta_research.md`.

## 6. Freeze declaration

The Alpha Research Laboratory architecture is declared **frozen** at commit
(see git HEAD for this file). Future work focuses on:

- new datasets (registration + quality grading)
- reusable features (implementation + campaign validation)
- research campaigns (backlog order: C002 → C003 → C004 → C007 → C011 → …)
- statistical validation (the C001 battery, DSR/RC for grids)
- accumulated market knowledge (edge DB, negative knowledge, meta-learning)

Software development is secondary to scientific research. The primary output
of the laboratory is reproducible scientific knowledge, not code.

## 7. Change policy

1. Registry changes (append-only additions, grading edits with reasons) are
   routine and do not require this report.
2. Architecture changes (new registry/store/document class, removal or merge
   of a canonical document, spec changes in `knowledge_graph.md` beyond
   append-only) require an entry in `research/meta_research.md` stating the
   scientific justification, and a re-run of the full audit.
3. This report is regenerated/reviewed at each quarterly review and after
   every campaign closure.
